# After the Sol snapshot: simplifying control roles

Decision note, 2026-09-05. This is a change to the operating recipe, not a
Slopdex source patch, runtime feature, or Astra-versus-Sol benchmark.

The first source drop preserves the profile used during the Sol-led campaign,
including `control-role-boundary`. At the start of the subsequent Astra field
work, the owner chose to retire that separate role-initialization layer from
the active recipe. A replacement role skill is not the plan.

The user should be able to give a project an ordinary task, without first
remembering a skill name or declaring the thread a parent architect. The model
can coordinate directly or use a separate operational coordinator when that
split actually helps. A coordinator may be valuable; it is not a mandatory
title or permanent rung in every graph.

## What stays

- Explicit scope, write ownership and one consumer for every child result.
- Native owned waiting and result admission; user steering keeps priority.
- Capability routing, useful decomposition and campaign dependencies.
- Independent verification where consequence warrants it.
- Separate owner authorization for external or consequential actions.
- Safe, non-overlapping transfer of existing execution ownership.

Removing the role shim does not remove these boundaries. A skill is behavioral
guidance, not an enforceable filesystem lease or a security boundary.

## What this publication preserves

The bundled skill files and global sample remain the historical Sol snapshot;
this note does not claim that every global installation has already been
updated. Shared-policy cleanup is a separate operation and should not be
duplicated by concurrent campaigns. Do not treat the retained role invocation
as a requirement for trying the source preview, or copy this historical profile
blindly over an existing configuration.

The [original shortgrid](../SHORTGRID.en.md) is not rewritten to pretend the
Sol campaign ran without that layer. This is the next step: retain useful
ownership mechanics while testing how much explicit role ceremony can be
removed. Early experience motivates the decision; it does not establish that
Astra never benefits from a coordinator, that all skills are unnecessary, or
that the change caused a measured speed or cost improvement.

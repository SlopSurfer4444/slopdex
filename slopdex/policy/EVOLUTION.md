# Less ceremony, same ownership

Recipe update, 2026-09-05. These are instruction changes, not Slopdex source
patches, runtime features or an Astra-versus-Sol benchmark.

The Sol-led campaign used an earlier operating profile. Subsequent field work
exposed instructions that added permission rounds without protecting another
boundary. The current bundle now follows the simplified recipe:

- No separate role-init skill or mandatory architect/coordinator tier. Give
  the project a task; add intermediate ownership only when it helps.
- Already-authorized offline implementation, tests and repairs continue
  without renewed approval. A failed review blocks acceptance, not repair.
- Repairs get fresh byte bindings. Preserve historical receipts and reuse
  evidence only while its source, dependencies and claims remain valid;
  refresh the affected proofs rather than blindly repeat everything.
- Reuse one compact campaign plan or ledger. Ordinary candidate progress is
  not a reason for a global replan or another document.

Scope, file ownership, one consumer per child, native waiting, connected tests,
proportional review, explicit user pauses and genuine safety stops remain.
External actions and consequential attempts keep their authorization and
outcome-reconciliation boundaries. A skill is guidance, not a filesystem
sandbox or a grant of authority.

The [earlier profile](https://github.com/SlopSurfer4444/slopdex/tree/f96a8db9cd4c9ab4fb0288e8b850da4be94ec302/slopdex/policy)
remains in Git history. The [original English shortgrid](../SHORTGRID.en.md)
and Sol source/test evidence are unchanged; the Russian setup example now
points to the current recipe. This cleanup does not claim a measured speedup,
that Astra never needs a coordinator, or that useful skills became obsolete.
